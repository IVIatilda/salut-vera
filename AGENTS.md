# AGENTS.md — правила работы с проектом Vera

Инструкции распространяются на весь репозиторий.

## Общение и принятие решений

- Общайся с пользователем на русском языке, если он не попросил иначе.
- Отвечай четко и по делу. Подробные объяснения давай по запросу или когда без них
  невозможно оценить существенный компромисс.
- Не соглашайся с предположением автоматически. Проверяй его по коду, данным,
  документации и ограничениям платформы. Если предположение неверно, объясни это и
  предложи подходящий вариант.
- Для безопасных решений в рамках задачи делай разумные допущения и продолжай работу.
  Спрашивай пользователя только тогда, когда выбор существенно изменит результат.

## Перед началом работы

1. Прочитай [docs/README.md](docs/README.md).
2. Прочитай документы, относящиеся к задаче:
   - [docs/01-product-spec.md](docs/01-product-spec.md) — продуктовая логика;
   - [docs/02-data-model.md](docs/02-data-model.md) — сущности и ограничения данных;
   - [docs/03-implementation-plan.md](docs/03-implementation-plan.md) — архитектура и этапы;
   - [docs/05-backlog.md](docs/05-backlog.md) — текущие и будущие задачи.
3. Проверь `git status`. Рабочее дерево может содержать незакоммиченные изменения
   пользователя или другого сеанса. Не удаляй и не перезаписывай их.
4. Изучи существующую реализацию затрагиваемого модуля и его тесты. Не делай выводы
   только по скриншоту или названию компонента.

## Продуктовые термины

- Название продукта — **Vera**.
- Используй термин **«Сфера жизни»**, а не «роль», в пользовательском интерфейсе.
  В старом коде и данных еще может встречаться `role`/`roleId`; не переименовывай их
  механически без отдельной миграции.
- «Ослабляемая привычка» учитывает нейтральные **эпизоды**, а не «провалы».
- Пропуск привычки не должен обнулять историю или наказывать пользователя.
- Автоматически полученные данные должны иметь видимый источник и возможность ручной
  корректировки.

## Архитектура

- Текущий клиент: React + Vite на JavaScript.
- Приложение — адаптивная PWA с local-first подходом.
- Текущее постоянное хранилище — IndexedDB через
  `src/shared/storage/indexed-db.js`. Облачного бэкенда пока нет.
- Будущие синхронизация, Node.js-бэкенд и PostgreSQL описаны как планы, но не должны
  имитироваться в UI как уже работающие возможности.
- Функциональные модули находятся в `src/features/<feature>/` и по возможности делятся
  на `components`, `model` и `data`.
- Общие переиспользуемые компоненты и инфраструктура находятся в `src/shared/`.
- Не складывай новые компоненты, модели и утилиты непосредственно в корень `src`.
- Не добавляй новую зависимость, если задача надежно решается существующим стеком.

## Данные и предметная логика

- Сохраняй бизнес-расчеты в функциях модели, а не внутри JSX, если они используются
  более одного раза или требуют проверки граничных случаев.
- Для каждой новой или измененной бизнес-логики добавляй либо обновляй тесты Vitest.
- Не изменяй существующую схему IndexedDB без явного повышения версии базы и проверки
  миграции. Существующие пользовательские данные должны сохраняться.
- Событийные данные не заменяй агрегатами без необходимости. Например, каждый эпизод
  ослабляемой привычки хранится отдельной записью с точным временем.
- Даты календарных дней храни в локальном формате `YYYY-MM-DD`; временные события —
  как timestamp. Не смешивай локальный день и UTC без явного преобразования.
- Не создавай фиктивный сетевой слой для функций, которые пока работают локально.
  Интерфейсы будущего бэкенда можно проектировать отдельно от реализации.

## Интерфейс и доступность

- Сохраняй существующий визуальный язык Vera: темно-синий, мятный и коралловый акценты,
  компактные карточки, спокойные состояния и нейтральная лексика.
- Новое действие должно быть понятно без чтения документации. Для кнопок только с
  иконкой обязательно задавай доступное имя через `aria-label`, а при необходимости —
  `title`.
- Состояние фокуса не должно выглядеть как ошибка. Ошибку обозначай отдельно и только
  после валидации.
- Проверяй адаптивность как минимум на узкой мобильной и обычной десктопной ширине.
- Не меняй глобальную стилистику в рамках локальной задачи без прямого запроса.
- Не используй нативные `<select>` там, где в проекте уже применяется единый
  `CustomSelect`.

## Документация и бэклог

- Если меняется пользовательское поведение, обнови `docs/01-product-spec.md`.
- Если меняется сущность, поле или правило хранения, обнови `docs/02-data-model.md`.
- Будущие идеи и зависимости фиксируй в `docs/05-backlog.md`, не выдавая их за
  реализованные функции.
- Для объемного отложенного решения создавай отдельный документ в `docs/` и добавляй
  ссылку на него в `docs/README.md` и бэклог.
- Не отмечай задачу в бэклоге выполненной, пока реализация и необходимые проверки не
  завершены.

## Проверка изменений

После изменений запускай проверки, соответствующие риску. Базовый набор:

```bash
npm test
npm run build
git diff --check
```

Для изменений интерфейса дополнительно проверь страницу визуально на десктопной и
мобильной ширине и основной измененный сценарий — кликом и с клавиатуры.

После браузерной проверки закрывай все вкладки, которые были открыты для тестирования.
Оставляй вкладку открытой только по прямой просьбе пользователя или когда она нужна
для явно согласованного продолжения работы в следующем сообщении.

Не исправляй посторонние ошибки и не форматируй несвязанные файлы без необходимости.
Если существующая ошибка блокирует проверку, зафиксируй это в итоговом сообщении.

## Git и файлы

- Не выполняй `git reset --hard`, `git checkout --`, очистку рабочих файлов или другие
  разрушительные команды без прямого указания пользователя.
- Не коммить изменения без явного запроса.
- `node_modules`, `dist`, временные файлы, логи и локальные конфигурации не должны
  попадать в репозиторий.
- Для поиска файлов и текста используй `rg`/`rg --files`.

## Завершение задачи

В итоговом сообщении укажи:

- что изменено с точки зрения пользователя;
- важные ограничения или принятые решения;
- какие проверки выполнены и прошли ли они;
- какие действия остались, только если они действительно необходимы.
